# 小说创作执行方式（Novel）

把 Reasonix 当作小说创作引擎：**你定方向，模型写整章，机制层保持长文不漂移**。三主线：**创造**（从想法到开书）、**续写**（从上一章接着写）、**改写**（局部重写/润色/反模板化）。

**执行边界**：创意理解、规划、生成、审查与判断由模型负责；**纪律由机制层保证**——`reasonix novel` 子命令持有工作区状态、章节指纹与下一步路由，不依赖模型记得保持连贯。文件工具读写工作区，ask 工具用于渐进确认。不引入外部依赖、不用数据库、不装 Python。

## ⚙️ 机制层（先跑命令，再动笔）

每次进入小说任务，**先运行 `reasonix novel status [书名]`** 定位进度，再决定动作：

| 命令 | 作用 | 何时用 |
| --- | --- | --- |
| `reasonix novel init <书名>` | 创建 `novels/<书名>/` 完整脚手架 | 新书开写前 |
| `reasonix novel status [书名]` | 输出最后稳定章节 + 下一步（唯一的进度权威） | 每次续写/恢复前 |
| `reasonix novel check <书名> <章节>` | 指纹校验正文是否被外部改动（stable/stale） | 发现状态可疑时 |
| `reasonix novel advance <书名> <章节>` | **登记稳定**：记录指纹并推进下一步（记忆唯一入口） | 正文验收通过后，一步别跳过 |

**关键纪律**：正文未验收前反复生成/重写都安全——只有 `advance` 会把版本写进账本。用户手动改过正文后，`check` 会报 `stale`：保护正文、标记依赖资产、从最终正文重新核对后再 `advance`。

## 工作区结构（novels/<书名>/）

```
novels/<书名>/
├── brief.md          # 定位：premise、目标读者/阅读回报、频道、故事发动机
├── bible.md          # 宪法：世界规则、写作规则、禁止模式、叙事默认(POV)
├── characters.md     # 角色档案 + 关系网络（父子/同盟/敌对/从属）
├── outline.md        # 四级大纲：总纲 → 卷(Arc 起承转合) → 章(最小单元)
├── foreshadowing.md  # 伏笔：active(planned_resolution)/resolved；可标 dramatize
├── style.md          # 风格库：原文片段（模仿笔风时逐字照抄优先）+ 写作偏好
├── state.yaml        # 进度（由 novel 命令维护，别手改）
└── chapters/chXXX/
    ├── plan.md       # 章节计划合同
    ├── draft.md      # 正文（可编辑）
    ├── review.md     # 验收结果 + 质量债
    └── delta.md      # 本章连续性变更（稳定后才写）
```

首次写书至少先建 `brief.md` + `bible.md` + `characters.md` + `outline.md`；每章可另写 `scenes/` 场景摘要（见下）。

## 创造（从零开书）

1. **无想法**：给恰好 5 条不同风格的一句话开书种子（废土、都市、玄幻、悬疑、日常各一），让用户选/改/自填。不直接开问设定。
2. **有想法**：生成两份**明显不同方向**的新书简报预览（标题/premise/读者回报/主角路径/核心冲突/开篇钩子/进展循环/结局方向），只放对话，**不写盘**。选定后再 `novel init` 落盘。
3. **渐进确认**：用 ask 每轮只问最关键的 2-3 项（推荐项在前）；确认或授权 AI 决定后，后续里程碑不重复询问（"以后这些不用问我"= 记为授权）。
4. **设定树（马良式）**：init 后按 bible/characters 模板生成**结构化设定树**——角色/地点/物品/势力条目 + 关系网络（父子/同盟/敌对/从属），条目可增量修改。内置题材模板（如"番茄风网文设定"）供参考。
5. **黄金三章**：开书设定确认后，一次生成**前三章的大纲 + 摘要**（网文开篇钩子方法论：首章钩子、次章升级、三章小高潮），用户选一章方向后再细化首章 plan。
6. **剧情推演（Next Outline）**：续写或卡住时，让模型给出 **3 个分支大纲选项**（走向/风险/读者回报各异），用户选定或单独重生成不满意的分支；选定后写进 plan。
7. 首章前必须确认或取得授权：叙事视角、节奏与语言倾向、单章长度、内容边界。

## 续写

1. **先 `reasonix novel status`** 定位：最后稳定章节、其实际尾段与净变化、下一步。
2. **上下文优先级**：本章计划 → 上一章实际尾段（摘要不能替代）→ 参与角色硬事实与当下呈现 → 禁止越界 → 当前卷窗口 → 世界规则 → 未兑现伏笔 → 风格合约。不默认读整本正文。**风格合约以 style.md 的原文片段为准**：模仿笔风时直接参照原文逐句调性（句式长短、停顿、叙述距离、吐槽节奏），AI 自写样文不得替代原文；style.md 无原文片段时，以已验收正文中与目标笔风最接近的段落为参照。
3. 写 `plan.md`（章节合同）→ 一次生成整章 `draft.md` → 反模板化二稿 → 验收 → **验收通过后**写 `delta.md` 更新角色/伏笔/场景摘要 → **`reasonix novel advance`**。
4. 现有计划与正文冲突：**保护正文事实**，再修订未写计划。
5. 每章正文稳定后写 **场景摘要**（每个场景 1-3 句精炼摘要到 `chapters/chXXX/scenes/`）；后续章节需要回忆时优先读摘要，需要细节时读对应场景正文（马良式双向：摘要→扩写回场景）。

## 改写

1. 先说明改写对象与影响范围（局部表达/章节义务/连续性/邻章分工/卷级结构），只改最小范围。
2. **锁定不可变项**：已发生事实、信息边界（knows/secrets）、物件归属、关系、章末钩子、时间顺序。
3. 保留已成立的爽点、转折、事实与角色声音。未经确认不得覆盖用户编辑过的正文。
4. 改写后 `reasonix novel check` 确认指纹一致，若用户手动改过则按 stale 流程重核。
5. 反模板化改写见下；不得用错别字/病句/随机细节/伪造经历制造"人味"。

## 章节计划合同（plan.md 必备项）

- **义务**：即时目标、主要阻力、参与角色及作用、必须推进的剧情与信息、必须保留的事实、必须触碰的伏笔、必须发生的角色目标变化、参与角色当下呈现、调用的世界规则与限制、可延后项、禁止越过的边界。
- **读者体验**：读者最关心的问题、本章回报强度（setup/partial/major）、主角即时欲望、关键转折、情绪位移、章末净变化、继承的旧钩子、新的章末牵引。
- **节奏段与篇幅**：3-5 个节奏段（开篇抓手→升级转折→回报与牵引），每段写明进入状态/动作与阻力/读者回报/预算字数/离场状态。目标字数 + 可接受区间；低于下限只补有效剧情（新行动/阻力/选择/对话冲突/关系变化），超长先删回顾/重复解释/无后果环境描写。

## 📗 轻小说适配（你的创作方向）

按轻小说文体特征执行，与通用流程叠加：

- **视角**：优先第一人称"我"或近距离第三人称——主角心理独白承担喜剧与信息双重功能；转生/穿越前提把"前世知识"写进主角的 `knows`，制造信息差。
- **结构**：文库一卷 ≈ 序章 + 12-20 话 + 章末（后记/次卷预告）；每话 3000-5000 字；话标题可长句式（"第1话 转生到异世界的我开始了打工生活"）；系列化：第一卷必须定基调并埋长线伏笔。
- **章末钩子（强制）**：每话结尾必须留悬念（新角色登场/危机逼近/告白未遂/真相一角）——轻小说追读率靠话末牵引，写入 plan.md 的"新的章末牵引"并纳入验收。
- **角色**：characters.md 用"属性标签 + 口头禅 + 称呼习惯"（傲娇/天然呆/腹黑/元气…）；恋爱喜剧用**好感度阶段**跟踪关系（陌生→认识→朋友→暧昧→恋人），每次 delta 更新关系温度；角色定位（女主/对手/吉祥物/吐槽役）决定其出场方式。
- **排版与节奏**：对话一行一段 + 空行分隔（轻小说视觉节奏）；短段落高频切换；吐槽（ツッコミ）紧跟傻桥段（ボケ）成对出现；拟声拟态词（ドキドキ/くすっ/ざわ…）适度点缀，不滥用。
- **设定说明**：异世界规则/系统面板用"讲解即推进"——边讲边推关系或冲突（参考技法章的场景 3 段上限）；系统面板信息可作章末钩子（"【叮——新的技能已解锁】"）。
- **反模板化（轻小说特有）**：每段都吐槽、模板化害羞反应（"脸红转过身去"）、万能"微微一笑"、口癖滥用（每句都带口癖）——成簇才修，保留角色辨识度。

## 技法（Openwrite 式 craft 规则）

- **对话节奏**：短促对话 1-8 字/句（争吵、审讯、危机）；标准 10-30 字（日常推进）；长篇 40+（说明、谈判）。对话轮次清晰时省略标签；标签只用于识别说话人与补充语气，不堆砌表演。
- **段落节奏**：长短参差，不连续 3 个以上同长度段落；短段提供呼吸点与重音；长段要有理由（策略推演、环境铺排、情感蓄力）。
- **场景节奏**：设定说明场景走"信息点→角色反应→追问/误解→新问题"结构；连续解释不超过 3 段就必须有人反应；讲解设定时也要推进关系、冲突或判断。
- **章内节奏**：每段结束时都应改变主角可做的事、读者知道的事、关系温度或风险等级；不把全部转折压到结尾。

## 反模板化二稿（推荐，成簇才修）

同一类问题**成簇出现**才修。常见 AI 腔与替代：

| AI 腔 | 替代 |
| --- | --- |
| "然而""不禁""不由得" | 删掉或换口语转折（但是/不过/可/却） |
| "微微一笑""嘴角微微上扬" | 笑了笑/咧嘴笑了（别所有角色一个笑法） |
| "眼中闪过一丝""若有所思" | 直接写眼神/动作变化 |
| "深吸一口气""缓缓" | 吸了口气/一点点，保留动作去掉模板 |
| "心中暗想""难以置信" | 让思考落在动作里；换"没想到/离谱" |
| 否定式并列（"不是 X，而是 Y"） | 从有效信息或行动直接写起 |
| 格言化旁白（"权力是……"） | 删；让场景承载 |
| 解释性推进（叙述者替读者说明） | 用动作/对话/物件承载信息 |
| 均质声音（所有角色同一句式） | 不同身份用不同语言风险偏好 |
| 泛化感官与抽象词（"压迫感""命运"） | 换成可触摸的空间/物件/身体反应 |

场景化手段：让人物说出不完全正确的话；用物件/停顿/被打断的动作承载情绪；保留一处不立即解释的观察让后文兑现。可重组段落。**锁定事实与信息边界不动**。

## 验收清单（写完/改完自查）

- 可读正文存在；must-hit 义务完成；无 forbidden 越界；主角主动；
- 回报/转折/净变化可感知；承接上一章；无硬事实冲突；
- 篇幅在可接受区间（偏差有明确剧情原因则不强行改写）；
- 节奏段兑现（开篇迅速进压力、中段真实升级、章末前可见回报、钩子承接净变化）；
- 无占位符/AI 自述/截断/工程词泄漏；无成簇模板化叙事。
- 缺失义务分类：patchable_obligation_gap（局部补写）/ rewrite_needed（整章重组）/ plan_misalignment（邻章失配才升级重规划）。

## 记忆与连续性（机制层纪律 + 账本）

- **记忆唯一入口**：正文稳定（验收通过）→ 写 delta 更新角色状态/伏笔/场景摘要 → `reasonix novel advance`。未 advance 的版本从未进账本。
- **指纹与 stale**：advance 记录正文 SHA-256。用户修改正文后 `check` 报 stale → 保护正文、标 stale、从最终正文核对后再 advance。
- 只有正文明确发生或审查确认的内容进稳定事实；计划内容不能提前写成已发生事实。缺失硬约束时**不臆造历史**——缩小本章行动或列入 review 风险。

## 失败处理

- 上下文缺失：明确缺失项，用保守默认，不编造精细历史。
- 状态索引与文件冲突：以受保护产物与稳定正文为准。
- 伏笔逾期：先作推进风险，不自动触发全书重规划。
- 质量债：正文可继续时记入 review.md，不伪装已修复。

**节奏提示**：生成 → 人工修订 → 验收 → delta + 场景摘要 → `reasonix novel advance`（一步别跳过）。
